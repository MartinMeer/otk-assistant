 Docker Refactoring Plan for OTK-Assistant

  Based on my investigation, here's a comprehensive analysis and refactoring plan for dockerizing your Spring Boot application:

  🔍 Current State Analysis

  Project Structure:
  • Spring Boot 3.4.1 application with Gradle build system
  • Main app in src/main/java/org/martinmeer/otkassistant/
  • Separate db-loader module (to be excluded as requested)
  • Uses PostgreSQL database
  • Has existing Dockerfile and compose.yaml but incomplete

  Configuration Files:
  • application.yml - sets active profile to "docker"
  • application-docker.yml - uses environment variables for DB config
  • application-test.yml - hardcoded test DB connection
  • Legacy config files in misc/ with hardcoded values

     5 │
     6 │   # Application
     7 │   SERVER_PORT
     8 │   SPRING_PROFILES_ACTIVE

    10 │   # CORS & API

    12 │   API_BASE_URL
    13 │
    14 │   # Logging
    15 │   LOG_LEVEL_ROOT
    16 │   LOG_LEVEL_APP

  2. Clean Up Legacy Config Files:
    • Remove hardcoded values from misc/psql_url.yml, misc/db_users.yml
    • Update misc/hibernate.cfg.xml to use environment variables
    • Clean src/main/webapp/META-INF/context.xml


  **Phase 2: Application Configuration Updates**

  3. Update Spring Configuration:

  4. Update OpenAPI Specification:
    • Make server URLs configurable via environment variables

  5. Fix Dockerfile:

  6. Enhance Docker Compose:

    • Health checks and dependencies
  7. Create Docker Environment Files:
